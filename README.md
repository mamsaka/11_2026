**Проект:** Автоматизированная система учёта заявок на ремонт оборудования

## Назначение системы
Система предназначена для приёма, обработки и контроля исполнения заявок на устранение неисправностей офисной и компьютерной техники. Заменяет бумажные журналы и позволяет отслеживать жизненный цикл каждой заявки.

## Стек технологий
- Язык: C# (WinForms)
- СУБД: SQLite (с поддержкой FOREIGN KEY через `Microsoft.Data.Sqlite`)
- Система контроля версий: Git (GitHub)

## Быстрый старт
Создать базу данных с нуля (из любой папки):
```bat
11_2026\SQL\create_db.bat
```
БД создаётся в `db/repair.db` и сразу заполняется тестовыми данными.

## Роли пользователей
1. **Сотрудник (Заявитель):** создаёт заявки, указывает оборудование и описание проблемы, отслеживает статус своих заявок.
2. **Специалист (Исполнитель):** просматривает все заявки, берёт их в работу (статус «В работе»), завершает (статус «Выполнена»).
3. **Администратор:** управляет справочником оборудования и пользователями, формирует отчёты.

## Бизнес-процесс
1. Сотрудник создаёт заявку (статус «Новая»).
2. Специалист берёт заявку в работу (статус «В работе»).
3. После устранения неисправности специалист закрывает заявку (статус «Выполнена»).
4. Администратор формирует отчёт по количеству заявок в разрезе статусов.

## Сущности и связи
- **Сотрудник** — заявитель: ФИО, должность, отдел, логин, пароль. Один сотрудник создаёт много заявок.
- **Специалист** — исполнитель заявок: ФИО, специализация, логин, пароль. Один специалист может быть назначен на много заявок.
- **Администратор** — управляет справочником оборудования и пользователями, формирует отчёты. Заявок не создаёт и не исполняет, поэтому с сущностью «Заявка» не связан.
- **Тип оборудования** — справочник категорий техники (ПК, принтер, сканер и т. п.). Один тип относится ко многим заявкам.
- **Статус** — справочник состояний заявки: «Новая», «В работе», «Выполнена». Один статус соответствует многим заявкам.
- **Заявка** — центральная сущность: номер, сотрудник-заявитель, тип оборудования, описание проблемы, дата создания, назначенный специалист, текущий статус.

Связи: `Сотрудник 1—N Заявка`, `Специалист 1—N Заявка`, `Тип оборудования 1—N Заявка`, `Статус 1—N Заявка`.

## Структура проекта
- `SQL/` — база данных и проектирование:
  - `er.mmd` — ER-диаграмма (Mermaid);
  - `er.svg` — отрендеренная ER-диаграмма;
  - `init_db.sql` — скрипт создания таблиц, связей и тестовых данных;
  - `create_db.bat` — создание БД одной командой.
- `db/` — рабочая база `repair.db` (создаётся скриптом, в Git не хранится).
- `README.md` — описание проекта, ролей и бизнес-процесса.
